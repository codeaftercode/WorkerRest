# WorkerRest 设置窗口 · 视觉语言规格（settings-restyle-spec）

> 适用范围：设置窗口全部组件的**颜色 / 阴影 / 圆角 / 图标 / 字重灰阶**。
> 边界（约束解禁后更新）：功能性红线两条——`#content` 的 border-right/bottom 6px 透明拖动带必须保留；最小窗宽 760 下所有页面不横向溢出、时刻表行不换行。布局几何已允许重定，新增建议见第六节；字号正文与标签锁定 14px 不变。
> 渲染环境：Wails v3 / WebView2（Chromium 120+），`color-mix()` 可用，但所有半透明色同时给出 rgba 等价值。

## 四、组件处理要点（视觉结论）

1. **侧栏 active / hover**：active = `--accent-weak` 底 + `--accent` 图标 + 文字 500；hover = `--panel-2` 底、图标与文字过渡到 `--text`。active 不加阴影、不加描边——当前态靠底色差表达，与卡头等可点元素（靠边框）形成两种语言。
2. **卡片**：静置只描 `--border`、圆角 13、无阴影；整卡不悬停上浮（设置页的卡片是容器不是按钮），可点的卡头 hover 时仅将自身描边过渡到 `--border-strong`。
3. **卡头拨动开关**：轨道 `--r-pill`；off 态轨道 `--panel-2` + `1px --border-strong`，on 态轨道 `--accent`；拇指纯白（深色用 `--panel` 提亮）+ `--sh-1`，off/on 切换只动轨道底色与拇指位移，不改拇指样式。
4. **输入框三态**：默认 `--panel-2` 凹底、无边框；hover 出现 `1px --border`；focus 边框转 `--accent` + 外圈 `--ring`（`box-shadow: 0 0 0 3px`）。深浅同构，只换令牌。
5. **下拉菜单**：`--panel` 底、圆角 9、`--sh-3` + `--float-border`（深色另加 `--float-inset`）；条目 hover 用 `--panel-2`，当前选中用 `--accent-weak` + `--accent` 文字。
6. **弹窗与 overlay**：遮罩浅色 `rgba(23,26,38,.45)`、深色 `rgba(5,7,14,.55)`；窗体圆角 13、`--sh-4`，深色补 `--float-border` + `--float-inset`。遮罩透明度刻意低于常见 SaaS（.45/.55 而非 .6+），让底层界面仍可辨——这是"提醒工具"，弹窗出现时用户不该失联。
7. **tooltip 与 "?" 浮层**：反色方案——浅色主题用深底 `#252a3a` + `#f2f4fa` 字，深色主题用 `#3a415c` + `--text` 字；圆角 6、`--sh-2`、字号 T2（12px）。反色保证在任何底色上都可读，不需要按宿主元素调。
8. **toast**：`--panel` 底 + `--border-strong` 描边 + `--sh-3`、圆角 9；左侧 3px 语义色竖条（success/warn/danger 取本体色），文字用对应 `-fg` 档。不上浮动画以外的动效。
9. **快捷键录入框**：空态 `--panel-2` 底 + `--text-3` 占位文案"点击录制"；录制中边框转 `--accent` + `--ring` 外圈（与输入框 focus 同构）；已录入键位用 kbd chip：`--panel-2` 底、`1px --border-strong`、圆角 6、T2 字号 500 字重。
10. **标题栏**：拖拽区与 `--bg` 同色、无边框无阴影，仅底部 `1px --border` 分隔（若侧栏已有分隔则连这条也省）；文字 T2（12px）+ `--text-2`。标题栏是整个窗口最安静的区域，任何视觉权重都是错的。
11. **侧栏快捷操作分组（GroupBox）**：外框 `--panel-2` 凹面 + `1px --border`、圆角 9（比所在 `--panel` 侧栏低一档，见 1.2），组内按钮凸回 `--panel` + `1px --border-strong`、圆角 6 —— **13（卡片）→ 9（框）→ 6（按钮）**，9px 的框里不再放 9px 的按钮，否则内外弧顶在一起。组标题 12px / 500 / `--text-2`，前置一枚 3×11 `--accent` 竖条（与提醒卡组标题同语言）；标题由 `<legend>` 承担，**底色必须是 `--panel`（侧栏色）而不是框内的 `--panel-2`**：浏览器把 legend 排在边框线上方半格，填框色会在框顶鼓出一条色带，填侧栏色才是「标题把顶线切开」的原生 GroupBox 形态。组内唯一的主动作（立即休息）用实底 `--accent` + `--on-accent` + 600，禁用时退回次动作外观并撤掉半透明（实底压到 40% 会透成脏蓝）；其余为次动作，hover 只把描边与文字转 `--accent`，`:active` 下压 1px，不加阴影。
    **组内每个按钮都带一枚 14px 图标**（`<span class="qa-ico" aria-hidden="true">` + 内联 SVG，`stroke="currentColor"` 继承按钮前景——不另写一套色，否则 primary 实底与 hover 转 accent 时就对不上）。图标与 12px 文案间距 5px，横向内边距因此从 8 收到 **6**：两列按钮宽 83.5，4 字文案 48 + 图标 19 之后只剩 4px 余量，再宽一点「重置周期」就会把字挤到换行。语义一一对应：立即休息=咖啡杯（**实心**杯身 + 描边把手：14px 上 1.8 描边的空心杯只剩一根发丝宽的白线，压在实底 accent 上根本看不清 —— 主动作本来就与其它按钮不同构，用实心字形换回可辨识度）、暂停休息=两条杠、**恢复休息=三角（靠 `.resuming` 切显隐，文案翻了图标必须跟着翻，否则「恢复休息」配个暂停符号自相矛盾）**、推迟休息=沙漏、跳过本次=实心三角 + 竖条、重置周期=圆箭（与「恢复默认」同一枚路径，全窗只有一种“重置”字形）。绘制只用 1.7–2.2 的线条与实心小三角，不上多色、不上投影；SVG 一律 `aria-hidden`，可访问名仍由 `.qa-txt` 提供。**图标要按「墨迹中心」对齐而不是盒中心**：12px 中文在 32px 按钮里 flex 居中后，字形墨迹中心在 16.73、行盒中心在 16（行盒给西文降部留的空档汉字不占，于是字整体坐在中线偏下），图标按盒居中（15.90）就会比文字高半格 —— `.qa-ico { top: 0.8px }` 把两者墨迹中心拉到同一水平线；相对位移不参与 flex 计算，不动按钮 32px 高度与两列网格。

## 五、取舍与代价

1. **阴影刻意压到接近不可见（浅色静置 alpha .05）**：放弃立体感与"悬浮高级感"，换 macOS 设置页那种纸面秩序。代价：浮层与底面的区分几乎完全押在 1px 描边上，深色端必须严格执行 `--float-border` + `--float-inset`，漏一处就糊成一团。
2. **卡片圆角 14 → 13**：所有引用旧 `--radius` 的位置统一降 1px。代价：视觉上卡片略"方"了一点点；换来的是三档圆角能真正嵌套（13−4=9 不成立，但 13→6 的内外差让输入框不再顶着卡片圆角"长出来"），散落 8 个值的局面被终结。
3. **深色实底强调色上不用白字（`--on-accent: #0f1730`）**：放弃"蓝底白字"跨主题的直觉一致。代价：与浅色端同一条主按钮看起来"反相"，需要接受这 1 处不对称；不换则白字对比 2.4:1，可访问性不达标，没有第三条路。
4. **语义色色相锚定图表色板**：放弃为语义单独选色的自由。代价：warn 永远是偏土的琥珀而不是更"醒目"的橙红，错误态不够"刺眼"；换来的是全窗只有 4 个彩色色相，pill、图表、toast 在视觉上自动同族。
5. **字阶砍掉 13px**：输入框文字与正文统一 14px。代价：参数密集的行会比现在高半档视觉密度，个别长输入串的可容字数变少（几何不动的前提下）；换来的是 5 档以内、无半档，维护时不再需要猜"这里该用 12.5 还是 13"。
6. **几何整体走"松"不走"紧"**（第六节：卡头 26→32、行高统一 40）：放弃信息密度，换一致的滚动节奏与更大的点击目标。代价：同屏可见行数减少约 5–10%。在"设置窗口"这种低频长驻场景里密度让位给呼吸感是划算的；若未来要塞进高频长列表，这一节几何需要重谈。

## 六、布局几何建议（约束解禁后新增）

前提——两条功能红线，本节所有取值以不违反为验收条件：

1. `#content` 的 border-right/bottom 6px 透明拖动带原样保留，任何新几何不得占用这 6px（无边框窗口 WS_THICKFRAME 依赖它）。
2. 最小窗宽 760 下所有页面不横向溢出；时刻表行保持不换行，宽度收缩由星期方块承担。

JS 依赖的 DOM 结构与类名不变——本节只改 CSS 里的尺寸值，不动结构。

### 6.1 最小窗宽横向预算（改造后核算）

```
760（最小窗宽）
− 224  侧栏
−   6  右侧拖动带
=  530  内容区
−  12  滚动条（约值）
−  32  卡片水平内边距（16 × 2）
≈ 486  字段行可用宽
=  216 标签列 + 12 列间距 + ≈258 控件区
```

控件区 258px 在最小窗宽下仍够滑条（≥160 即舒适）与常规输入框；比改造前（200 + 12 + 262）净让出约 4px，换来的是标签彻底脱离 13px 字号补丁。

### 6.2 逐项建议

| 项 | 现值 | 建议 | 理由 | 代价 |
|---|---|---|---|---|
| 侧栏宽度 | 240px | **224px** | 6 个导航标签最长 4 字（"时间规划"/"统计报表"），图标 20 + 间距 10 + 文字 56 + 内边距 32 ≈ 118 已足够，240 是虚胖；让出的 16px 直接补给标签列 | 状态格与快捷操作按钮组变挤；若状态格现为两列并排，224 下需改纵向堆叠 |
| 标签列宽 | 200px | **216px**，同时**废除 13px 字号补丁** | 14px 下容纳约 15 个汉字，覆盖绝大多数标签；剩余长标签允许换行至 2 行（line-height 20px，行内垂直居中）——用换行治长句，而不是用缩字号治 | 最小窗宽下控件区让出约 4px；个别双行标签使相邻行高不齐 |
| 行高节奏 | 40 / 36 | **统一 40px** | 40 与 36 只差 4px——一致到不像有意的层级，又差到不成体系，是"意外产物"不是设计；统一后勾选行与字段行滚动节奏对齐 | 长勾选分组页总高增约 10%；设置页不参与密度竞争，可承受 |
| 卡头高度 | 26px | **32px** | 拨动开关约 20px 高，26px 只剩上下各 3px，hover 描边转强时开关贴边发闷；32px 给开关、箭头上下各 6px 余量，卡头的可点目标也更稳 | 每张折叠卡增高 6px，一屏约少 0.5 张卡；折叠态更显"块" |
| 时间规划缩进 | 24px | **一级维持 24；若存在二级嵌套，二级以 +12 递增（24→36→…）而非 ×2** | 时刻表行永不换行，横向宽度是硬预算，24×2 的全量缩进在最小窗宽会挤压星期方块的收缩余地；12px 递增配合已有的竖线/方块标记，层级辨识不靠缩进独扛 | 二级与一级缩进差缩小，深层扫读时层级感略弱，靠竖线补足 |
| 卡片内边距 | 未统一 | **水平 16 / 上下 12** | 16 与间距标尺（8/12/16/24）对齐，且 ≥ 圆角 13 的安全内距；上下 12 避免与 32px 卡头叠加成过厚留白 | 若现值小于 12，长表单页总高增加 |

### 6.3 维持现值、明确不改的

- `#content` 6px 透明拖动带：功能红线，不动。
- 页面级左右边距、卡片之间间距：未见实测问题，不为改而改。
- 统计页表格与图表区几何：不在本次解禁动机内；图表六色数据系列维持原值（见 1.8）。

补充：本节所有新值都落在既有间距标尺（8/12/16/24）内，没有发明新间距档；字号不新增档位，13px 补丁的废除与第二节"13→14"的归并方向一致。
