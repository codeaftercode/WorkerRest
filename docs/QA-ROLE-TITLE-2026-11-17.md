# 立绘题名牌 · 极端用例压力测试（2026-11-17）

对象：休息提醒窗 / 竖屏提醒窗 / 外卖提醒窗里的**督休专员题名牌**
（`.dialog-name`，竖排单列金字 + 红印泥墨块，位置与字号由 `layoutRoleTitle()` 按立绘
alpha 剖面反解）。两份实现：`break.js`（休息窗，横竖两版式共用）与 `takeout.js`（外卖窗）。

探针：`scripts/probe/probe_role_title_stress.py` + `role_title_stress.js`
（`probe_role_title.py` 只跑真实专员名，最长 10 字；这一套专门跑极端名）

## 一、覆盖面

**用例矩阵 = 26 组极端名 × 3 版式 × 15 位专员**，另加每组版式的附加场景：

| 维度 | 取值 |
|---|---|
| 长度 | 1 / 2 / 10 / 16 / 21 / 29 / **30（UI 上限）** / 42 / **60（Go 上限）** / 120 / 200 |
| 字形 | emoji、ZWJ 家庭、日文、韩文、泰文（组合符）、阿拉伯文（RTL）、全角拉丁 |
| 边界 | 含省略号、HTML 标签、首尾空格、中间点、换行、31 拉丁带空格、空名 + 空名后恢复 |
| 版式 | 1100×720 横屏 / 760×980 竖屏 / 880×560 外卖 |
| 附加 | 改名风暴 ×8、同尺寸重复（墨块缓存）、窗口扫掠 760×520→760×1400→1600×600→1100×720、立绘极端（高度 20~100 / 距左 0~30 / 距底 0~40）、DPI=2 对照 |

断言 17 条/例：已定位、竖排、单列、与立绘重叠 ≤ 上限、**立绘在牌之上**、字号 15~26、
文字合法（原名或合法中间省略）、省略标记自洽、不溢出牌面、整块在窗口内、不压对话框、
墨块 viewBox==实测像素、碎点画布==牌子+2×10px、无 JS 错误、无横向溢出、重排不卡顿。
另有三条**元断言**（策略级，不看单条）：放宽重叠用例占比 < 25%、全量最大重叠未超上限、
本轮确实走到了省略分支。

## 二、结果

```
15 位专员 · 1380 条用例 · 29310 项断言 · 0 失败 · 0 处已知问题
```

| 指标 | 实测 |
|---|---|
| 字号区间 | 15.0 ~ 26.0 px（短名保满 26，长名守住可读下限） |
| 触发中间省略 | 21% / 18% / 25%（横屏 / 竖屏 / 外卖），矩阵内共 265 次 |
| 单列 | 全部用例单列，无一次折列 |
| 与立绘重叠 | 最大 **0.197**（上限 0.20）；1320 条已定位用例里只有 **53 条（4.0%）** 走了“放宽轮”，其余**全部零重叠** |
| 墨块 | 全部 `data:seal`，viewBox 恒等于牌子实测像素（无拉伸） |
| DPI=2 对照 | 与 1x **字号、盒尺寸逐项相同**（10 字 26px/49×314，30 字 15px/35×408） |
| 改名风暴 | 8 次同步改名+重排后终态就是最后一个名字，无残留/竞态 |
| 同尺寸重复 | `sealKey` 复用（35x408#…），墨块没有重画 |
| 窗口扫掠 | 四个尺寸连续 resize 后均重新定位、hit=0 |
| 视觉外扩 | 二阶段凑近（scale 1.08/脉动 1.095）最大 11.1px（设计效果，见四-3） |

### 重排耗时（长度 → 中位数 / 最大值）

| 长度 | 中位数 | 最大 |
|---|---|---|
| 1 字 | 4ms | 7ms |
| 10 字 | 24ms | 31ms |
| **30 字（UI 上限）** | **64ms** | 70ms |
| 120 字 | 116ms | 121ms |
| 200 字 | 147ms | 154ms |

单次重排 = 逐档试字号（26→15，步长 0.5）× 两种贴法 + 逐字递减求省略长度。
30 字是滑条真能到的上限，64ms 在窗口出现那一刻完全不可感知；200 字（只能靠手改
settings.json 到达，Go 侧另有 60 rune 的闸）147ms 也远低于 800ms 卡顿线，**不必优化**。
真要优化只需把省略长度的线性递减换成二分（最多 8 次测量而不是 196 次）。

## 三、本轮修掉的三处

### 1. `takeout.js` 漏写 `data-rt-elided`（P2，真不一致）

`break.js` / `settings.js` 都在牌面被省略时写 `data-rt-elided="1"`，外卖窗那份没写 ——
牌面照样省略，但标记永远为空。历史探针只校验 `textContent` 是否合法省略，没读这个标记，
所以一直没暴露；本轮压力探针断言“省略标记与文本自洽”当场红了 6 例。
现已补齐（与 `break.js` 同口径：省略时写 1，不省略时 delete）。

### 2. 牌面上缘出窗时被裁掉半个字（P2，真实可达）

立绘被滑条推到窗口外时（**高度 100% + 距底 40%**，两项都在滑条量程内），题名跟着头部
出窗：实测 `top = -12px`（第一个字被窗口切掉约 2px）到 `top = -300px`（只剩尾巴）。

改法（`break.js` / `takeout.js` 同步）：

- 新增 `topPx`：`visTop < 0` 且“整块下移到窗口上缘”**不新增遮挡、不压对话框**时下移；
- `fits` 增加上界 `topPx + padTop >= -4`：允许裁掉牌子的**上内边距**（那截墨块不带字），
  裁到字形就判不可行 → 退更小字号/更短省略 → 最终宁可整块不显示。

效果：`高度 100%` 这种常见配置（出窗 12px、牌子上内边距 10~14px）现在**完整可见**；
`距底 40% + 满高` 这种把整个头推出窗口的配置，改成“不显示”，而不是显示一截没有开头的
竖排字。纵深变化只在 `visTop < 0` 时发生，正常配置一位不受影响（回归见第五节）。

### 3. 允许牌与立绘少量重叠，立绘在上层（P2，用户 2026-11-17 定规则）

规则：左侧空间不够时，牌可以与立绘**少许**重叠，立绘显示在上层，牌被挡住一部分。

三个实现要点，每个都踩过坑：

**① 层序**。牌 `z-index` 从 9 降到 **7**，夹在 `#vignette(6)` 与立绘之间（休息窗口靠
`.stage(8)` 整体盖住牌）。不能降到 6 以下 —— 二阶段暗角 `opacity: 0.85` 会把金字压成褐色。
外卖窗口的 DOM 顺序是 `figure → 牌 → content`，`z-index` 同级会靠 DOM 顺序赢，所以
必须把 `.figure` 从 7 提到 **8**（仍低于 `.content` 的 8/9，对话框照旧压住立绘下半身）。
探针新增一条断言：牌与立绘在**公共祖先层叠上下文**里的绘制次序（`figLayer > nameLayer`）。
不能直接比两个元素的 `z-index` —— 休息窗口立绘在 `.stage` 内部（自身 7），比出来是 7 vs 7
看着同级。负向验证过：把牌改回 9，断言当场报 `figLayer=8 nameLayer=9`。

**② 重叠的量法**。第一版用「牌底 − 该列 minY」按列取差，**错得离谱**：画家举起的画笔
斜穿过牌的上角，逐列 minY 差值算出 38% 重叠，实际只压掉几十个像素，肉眼完全看不出遮挡
（截图核对才发现）。改为 `pf.solid` 逐像素位图，统计牌矩形内有多少不透明立绘像素，
同一用例的真实值是 **0.012**。代价是每张立绘多 200KB 内存（360×H 位图，只缓存当前立绘）。

**③ 求解器分两级**。第一版只有一个阈值 0.45，结果算法会**主动**把牌推到阈值上限换大字号
—— 实测 59% 的用例压在 40% 以上，那不是“必要时才压”，是“能压就压”。改为：
先按 `limit=0`（完全不碰）求最大字号，**全字号都不成立**才退到 `RT_OVERLAP_RATIO=0.20`。
全量结果：放宽轮只占 **4.0%**（53/1320），其余全部零重叠，最大重叠 0.197。

观感：被压住的是牌的一条边（画笔、发丝、衣角），26px 字的牌约 8~9px 宽，字形完整。

## 四、遗留问题（已记录，未擅自改设计）

### 1. 画家 × 竖屏窗口（**已解决**，但根因与本报告上一版写的不一样）

上一版把这条判成“立绘占满左侧竖条、名字无处可放”。改成允许重叠后一测，**根因不是空间
不够**：画家的长名在竖屏下其实只和立绘重叠 **1.2%~4.4%** —— 是它**举起的画笔**斜穿过牌子
左上角，而旧判据是“一个不透明像素都不许碰”，于是 15 列被画笔带过就整块判死。
换句话说，那 38% 的“重叠”是错误量法算出来的，实际只压掉几十个像素。

修完之后该组合 26 组名字全部正常显示（26px），`KNOWN_ISSUES` 已清空。原先设想的
“第三种贴法（退到窗口右侧）”不需要了。

顺带修了探针自身的一个排序问题：空名用例（本来就该 `positioned=false`）先被
`known_hit` 命中，导致 `[known]` 打印的是 `break@760x980`，把真正的失败盖住了。

### 2. 牌贴窗口左缘时碎点环带被裁 10px（既有）

`RT_EDGE = 6` 而碎点环带固定 `10px`，贴边那侧的碎点被窗口边界切掉 4px。观感上是墨点
到窗边就断，可接受；改 `RT_EDGE` 会动到 hit 判据（窄牌本来靠贴边多挤几个字），收益不划算。

### 3. 二阶段凑近带来视觉漂移（设计效果）

`.dialog-name` 与立绘共用 `scale`（1.08，脉动到 1.095），`transform-origin` 在双脚。
牌子在双脚左侧，于是放大时整体左漂：立绘距左 5% 时约 1px，距左 30%（滑条上限）时
实测最大 **11.1px**。这是“牌子和人一起凑近”的必然结果，若追求零漂移需要改缩放原点，
会让牌子相对头部错位（代码注释里已论证过），故保留。
