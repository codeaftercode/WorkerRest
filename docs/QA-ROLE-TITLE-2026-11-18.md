# 题名牌落位：牌心落在头肩中点 + 左侧舒适缝（2026-11-18，三轮）

## 需求（四轮）

1. **「在提醒窗口中，名称及墨块的位置太靠上、太靠近立绘了。改成在头部以下、肩膀以上的合适位置，
   可行吗？对现有的所有立绘都做测试。」**
2. **「不是“能有多低就多低”，是让整个名称的中间位于头顶到肩膀中间的位置，不要离开头部太远。」**
3. **「有一些名称离立绘头部太近了，有一种压迫感。如果左侧有很大的空间，可以适当往左一些。
   提醒你不要为每一个督休专员写死名称显示位置，因为用户可以上传新立绘，所以位置必须动态计算！」**
4. **「名称和墨块整体加一点透明度」**

第二轮是对第一轮实现的纠正，先把第一轮错在哪说清楚，否则改不干净；第三轮只动**横向缝**，
第四轮只动**整体透明度**，竖向锚点（牌心 0.17）始终不变。

## 第一轮错在哪：锚的是“牌顶”，不是“牌心”

第一轮把 `0.28` 当**牌顶**的位置（`topPx = visTop + visH × 0.28`）。可牌是一竖条：
2 字牌的**高度约占立绘可见高度的 15%**（26px 字 + 内边距 ≈ 95px，可见高 650px）。
牌顶落在 28% 时，牌心实际在 `28% + 7.5% ≈ 37%` —— 也就是**胸口**。

用户看到的“能有多低就多低”就是这个：约束写在牌顶，牌越长重心越往下掉，而求解器又是
“位置优先”（牌顶锁死、只缩字号），于是每一张图都稳定地把牌子放在胸口那一档。

## 现在：锚牌心

| 量 | 值 |
|---|---|
| 目标牌心 | `wantMid = visTop + visH × 0.17`（立绘可见高度 17% = 头顶到肩线的中点） |
| 牌顶 | `topPx = wantMid − 牌高/2`（**随字号变**：字号越大牌顶越高，牌心不动） |
| 两头夹紧 | 牌顶 ≥ `topFloor = max(visTop, 0)`；牌底 ≤ `bottomLimit = 对话框顶 − 12` |

改成牌心之后有两个附带好处：

- **字号越大牌顶越高，而不是往下长** —— 长名字不会把重心甩到胸口（10 字牌以前顶在 28%、
  底到 85%，现在围绕 17% 上下对称展开）；
- **左侧留白变宽**（牌横跨的是脸侧，比肩旁那条缝还窄，但因为不再往下压，整体遮挡反而下降）：
  压力矩阵平均重叠 7.8% → 3.9%，45 个真实用例全部拿到 26px 上限字号。

## 0.17 是怎么来的

15 张内置立绘逐张量 alpha 轮廓，用「行宽首次 ≥ 头宽×1.12」定肩线：肩线占可见高度
**27.6% ~ 42.2%**（中位 33.1%），取一半 = 16.5%，圆到 **0.17**。

**试过逐图检测肩线再弃用**：这条判据依赖“头宽”，而帽子（魔法师帽檐比肩还宽）、斗篷、
举起的画笔都会把头宽量错；逐图算出来和固定值只差 10px 上下，代价是“这位专员偏高、那位偏低”
的不一致。名称牌要的是整齐，所以留一条比例。颈部依旧不能靠“宽度局部最小”找 —— 发丝/高领/
围巾会把颈部糊平，实测漂到 45%~54%（那是腰和腿）。

## 第三轮：横向缝从“固定 12px”改成“12 / 32 两档”

竖向不动，只解决“贴脸”。旧实现里牌右缘到人物最左列恒留 `RT_GAP = 12px`：对 26px 的字
这只有**半个字宽**，牌右缘几乎贴着鬓角，看着就是压在脸上 —— 这就是“压迫感”的来源。
左侧明明还有几十像素空白，却没有理由往左走（12 是常量，不是判据）。

现在分两步：

1. **先求可行位**：仍按 `RT_GAP`(12) 求字号 —— 这一步决定字号能多大，不能被“好看”干扰；
2. **再试舒适缝**：左侧富余时整块左移到“牌右缘离人物 `RT_GAP_COMFORT`(32)”，前提是挪完
   左缘仍 ≥ `leftMin`（缩放预留），放不下就原地不动。

| 量 | 值 |
|---|---|
| 最小缝 | `RT_GAP = 12`（不糊在一起） |
| 舒适缝 | `RT_GAP_COMFORT = 32`（≈1.2 字宽，读得出“牌和人是两件事”） |
| 舒适缝的前提 | `bl − 牌宽 − 32 ≥ leftMin`（否则退回最小缝，绝不为了拉开距离去贴窗口边） |

为什么上限是 32 而不是“能放多左就多左”：宽屏里人物偏右时左侧空白可能上百像素，缝无上限会把
牌推成一张飘在半空、和人物失去隶属感的标签。32 是“明显离开脸、又还挂在人身上”的一档。

**为什么不会把字号挤掉**：挪左只会让遮挡变少，`fits` 的右界也更宽松 —— 原本成立的档位不会
因这一步失败。实测 45 例字号一例没变（仍全为 26px），因为压人的那 14 例左侧根本没有富余。

**没有任何 per-role 常量**：`bl` 由 `bodyLeftIn()` 按**牌子自身纵向跨度**从立绘 alpha 剖面里
逐图量出（`rowLo/rowHi`，翻转时镜像），窗口尺寸、字号、用户新上传的立绘都会让 `bl`、`leftMin`、
`slack` 自己变。源码注释里出现的专员名只是实测记录，不是配置表。

顺手修掉一个“先选字号再落位”的隐患：`at()` 现在返回的遮挡值就是**最终 left** 下的遮挡，
`toe` 循环与 `fits` 判据看的都是同一个位置，不会出现“记录的是 A 位置的遮挡、画在 B 位置”。

## 第四轮：整块（金字 + 墨块）opacity 0.85

用户：「名称和墨块整体加一点透明度」。

**为什么不拆开降**：墨块是 `background-image` 的第二层（裁进 `border-box`），金字是第一层
（裁进字形）。只给墨块降透明度会让金字从红底上“浮”起来，看着像两层贴纸；整块一起降才像是
一枚盖在画面上的章。所以只在 `.dialog-name` 上加一条 `opacity`，`break.css` / `takeout.css` /
`settings.css`（预览）与 `docs/design` 副本同值。

| 值 | 观感（同一张「医生」局部对比） |
|---|---|
| 1.0 | 朱砂厚实，完全遮住背景 |
| 0.88 | 与 1.0 几乎分辨不出（局部截图看不出差别） |
| **0.85** | 红底略透、仍像朱砂；金字柔一档但清晰 —— **采用** |
| 0.72 | 深蓝背景透上来，朱红发暗紫，开始“脏” |

两个副作用都查过：

- `opacity < 1` 会创建层叠上下文，但 `z-index: 9` 仍按父级参与排序（立绘 8 在下面），
  `probe_role_title` 的层序断言照旧通过；
- `probe_seal_ink` 量的是 `seal.js` **离屏渲染**的 alpha（铺满 / 孔洞 / 断裂），不经过这条
  CSS 规则，28 项判据不受影响。

## 已知代价

1. **牌横跨脸侧**：竖屏的野蛮女友、霸道总裁会被鬓角/发缘压住 12%~14%（牌在人物之上，字形完整）。
   第一轮那种“零重叠”靠的是把牌放到肩旁的空白里 —— 位置一抬就没有那条空白了，这是取舍。
2. **长名字牌会顶到窗口上沿**：10 字以上仍是“缩字号 + 中间省略”（与第一轮同）；牌心 0.17 之上
   只剩 17% 可见高度，牌太高时由 `topFloor` 夹住、牌心随之上移，探针按 `toe` 放过。
3. **设置页预览**用同一口径反推（可见高度 17%），但预览面板与真机窗口的可见区不完全等高，
   牌的相对位置会差几个像素 —— 预览只做“大概在哪”的示意，不参与真机求解。预览面板本身
   只有约 670×377 且人物靠左，横向缝实测是 2~6px，达不到 32：能示意的只是“牌在人的左侧、
   和头同高”，缝的宽度以提醒窗为准。
4. **人物贴窗口左缘的立绘仍有“压人”观感**（14/45，最大 13.8% 重叠）：左侧连 12px 都腾不出来，
   牌只能压住鬓角/袖口（牌在人物之上，字形完整）。要彻底消掉得把牌挪到人物右侧或头顶上方，
   那是另一套布局，超出“往左让一点”的范围。
5. **整体 opacity 0.85 会略微拉低金字与红底的有效对比度**（按深蓝背景粗算 2.62:1 → 2.42:1，
   一成以内）：题名是装饰性文字，`a11y_audit.js` 不覆盖它（只测设置页主按钮），所以没有
   量化断言。若以后要做无障碍，得先提亮金字（`#c19434`）而不是把 opacity 调回去。
