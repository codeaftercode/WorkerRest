# 题名 / 墨块极端输入验收（2026-11-18 第五轮）

前四轮（`QA-ROLE-TITLE-2026-11-17`、`QA-ROLE-TITLE-2026-11-18`、`QA-SEAL-INK-2026-11-17`）的
输入只有一样东西在变：**名字**。立绘始终是内置那 15 张——而这正是产品最不可能受限的地方：
用户能导入任意 PNG，第 3 轮定下的「位置必须动态计算、不许为每个专员写死」就是为了这个。

所以这一轮把**立绘本身**变成输入维度：现场生成 14 张互相矛盾的立绘，走生产导入同一条路径
（`WR_SUPERVISORS_DIR` → `ScanRoles` → `ToDataURL` → `<img src>`），再把名字矩阵、窗口矩阵、
DPI 矩阵压上去。目标不是"多跑几条用例"，是回答一个问题：**用户能上传的最坏一张图，会不会让
题名消失、跑到窗口外、或者把整页 JS 打断。**

## 这一轮查出并修掉的三个缺陷

### 1. 全透明立绘让整页 JS 崩在 `applyFigureTrim`

- **复现**：`showName` 正常、立绘全 alpha=0 → 控制台
  `TypeError: Cannot read properties of undefined (reading 'toFixed') at break.js:103`，
  `.figure-img` 没有 `dataset.trim`，题名永远不定位，探针全部只看到 `SCENE 版式起不来`。
- **根因**：`measureFigureTrim()` 在 `bottom < 0`（整图透明）时早退返回 `NONE`，而 `NONE`
  缺 `rawLeft/rawRight/rawTop/rawBottom`；`applyFigureTrim()` 无条件读 `t.rawLeft.toFixed(4)`。
  正常立绘永远走不到这个分支，所以内置 15 张立绘测四轮都没暴露。
- **修复**：`break.js` / `takeout.js` / `settings.js` 三份 `NONE` 补齐四个 raw 字段（并注明
  "兜底值必须字段齐全"）。
- **证据**：修复后全透明 / 坏图 / 仅下半身三类各 25 条用例全部「不可见 + 无 JS 错误」，`pageerror` 为 0。

### 2. 长名字牌心掉到胸口（0.27~0.35）

- **复现**：`30字` 牌心 0.35、`10字` 0.273（修前），违反「牌心 = 可见高度 × 0.17」。
- **根因**：`topFloor = max(visTop, 0)` 把牌顶锁在**头顶**。10 字牌高 314px，而 0.17 之上只有
  2×0.17×576 ≈ 196px，牌放不进去就只能把牌心往下推。
- **修复**：`topFloor = max(0, appRect.top)` —— 牌允许向上伸进头顶以上到窗口上缘的空白。
- **证据**：修复后 `mid` 落在 0.118~0.230；**全部 177 条 `mid > 0.19` 的用例，牌顶都正好贴在
  窗口上缘**（`lTop ≤ appTop+0.6`），即都是被窗口物理夹住、不是算错。探针用
  `lTop ≤ appTop` 识别 clamp，clamp 后不再判 0.17。

### 3. 中间省略把 emoji / 国旗 / 组合音标劈成残片

- **复现**：`👨‍👩‍👧‍👦×20` 显示成 `👨‍…`；`🇨🇳` 显示成 `🇯`（剩半个区域指示符）；
  `🧑🏿‍🚀` 显示成 `🧑🏿‍…`。
- **根因**：`[...fullName]` 按**码点**切。ZWJ 家庭 7 个码点、国旗 2 个区域指示符、`é` 是
  `e`+U+0301、肤色是独立修饰符——切哪一刀都会留下半个字。
- **修复**：`break.js` / `takeout.js` 新增 `splitGraphemes()`（`Intl.Segmenter` +
  `granularity:"grapheme"`，`Segmenter` 不可用或抛错时退回 `Array.from`），
  `settings.js` 预览用同口径 `pvGraphemes()`。
- **证据**：探针新增 `valid_grapheme_elide()`——省略号只允许出现在字素簇边界上，且头尾都是原
  名字簇序列的前缀/后缀；279 条省略用例全过，含 ZWJ/国旗/肤色/组合音标/CJK 扩展B/孤立代理项。

## 174 条"不显示名字"逐条可解释

| 角色 | 隐藏条数 | 原因 |
|---|---|---|
| 极端隐藏名 | 25 | `showName: false`，产品设计如此 |
| 极端全透明 | 25 | 没有任何可见像素，`headProfile` 全空 |
| 极端坏图 | 25 | 解码失败，无立绘 |
| 极端仅下半身 | 25 | 内容在 y≥68%，头顶落在窗外、`headBand` 里没有头 |
| 极端一像素 | 24 | 1×1 拉到窗口等于一个色块，`MAX_SCALE=4` 后仍无可用头部剖面 |
| 极端无透明 | 8 | 满铺矩形没有一处空白，3 字以上任何位置都超 20% 重叠上限 |
| 极端细条 / 极端贴左 / 极端窄高 | 18 / 12 / 12 | `420×300` 放不下（宽 1600 全景、6px 细条），或极窄人形头部列宽 < 牌宽 |

判断标准写死在探针里：**隐藏用例必须"不可见 + 文本回原名 + 无 JS 错误"**，只有三条同时成立
才算合格；一条不成立就是红。

## 物理约束（不是 bug，写下来免得下一轮重查）

1. **牌高上限 ≈ 2 × 0.17 × 可见高度**。超过就只能往上顶到窗口上缘，牌心被迫大于 0.17。
   这就是 `30字`+ 长名在 `760×600` 上的必然结果，探针按 clamp 放过。
2. **窗高 < 600**（`420×300`）时可见高度只剩 240px，0.17 之上只有 80px，几乎任何多字牌都会
   被夹；此时牌心上限按 0.45 放宽。
3. **满铺无空白立绘**（矩形）只有 3 字以内能放：没有空白可借，牌只能压在人身上，而 20% 重叠
   上限决定了牌宽上限 ≈ 0.2 × 可见宽度。
4. **`mid` 出现负值**（极端全景 −7.82、细条 −0.13）是立绘完全在窗外或极扁时的几何退化：
   可见高度趋近 0，比例失去意义。这些用例探针不判 0.17，只判"不溢出、不越界"。

## 遗留

1. `420×300` 低于产品最小窗口（`SettingsWindowMinHeight=600`），本轮只验"不崩、不越界"，
   没有要求排版好看。
2. `极端无透明` 与 `极端全景` 在最小窗口下的隐藏属于取舍而非缺陷：要么压过 20% 重叠、
   要么不显示，本轮选后者。
3. 墨块只验了尺寸/种子/契约这一层；**牌面宽度变化带来的撕口密度**（视觉）仍需目检，
   本轮 10 组尺寸各抽 2 块看过，未做量化。
